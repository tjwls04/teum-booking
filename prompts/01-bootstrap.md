# 첫 실행 요청문 — native Next.js 기반 만들기

Cursor에서 `teum-booking-native` 폴더를 열고 Codex에 아래 실행 요청문을 전달하세요. **지금은 이 작업 하나만 실행합니다.** 다음 단계는 결과를 검토한 뒤 현재 코드에 맞춰 진행합니다.

## 실행 요청문

```text
당신은 이 프로젝트의 구현 담당자입니다. 이 폴더의 AGENTS.md와 docs/PROJECT_CONTEXT.md, docs/PRD.md, docs/ARCHITECTURE.md, docs/ROADMAP.md를 먼저 읽으세요.

이번 목표는 macOS에서 실행·검증할 수 있는 native Next.js 프로젝트 기반입니다. 실제 로그인, DB 연결, 예약, 예약금, 결제, 외부 알림은 다음 단계입니다.

1. 현재 작업 폴더, 파일 목록, Git 상태, Node/npm/Git 버전을 확인하세요. 비밀 파일 내용이나 자격증명은 출력하지 마세요. 기존 사용자 변경사항을 보존하세요.

2. 환경에 따라 진행하세요.
- 문서만 있는 폴더: 문서를 유지하고 이 폴더에 native Next.js 앱을 구성합니다. 생성기가 빈 폴더를 요구하면 안전한 임시 폴더에서 생성한 뒤 필요한 앱 파일만 옮기세요. 기존 AGENTS.md/README/docs/prompts를 생성기 결과로 덮어쓰지 마세요.
- 이미 native Next 프로젝트: 필요한 부분만 보완하세요.
- 기존 Vinext/Vite/Cloudflare/Sites 프로젝트: 원본을 보존하고 teum-booking-native라는 별도 형제 폴더에서 구성하세요. 이미 같은 폴더가 있으면 내용을 읽어 충돌을 피하고 최종 경로를 보고하세요. 새 폴더에 이 묶음의 최신 AGENTS.md/README.md/docs/prompts를 유지하고 이후 기준을 새 폴더로 전환하세요. 최신 문서 묶음이 보이지 않으면 이전 Sites 문서를 복사해 대체하지 말고 문서 묶음 폴더를 Cursor에서 여는 단계로 안내하세요.
- Node/npm이 없거나 호환되지 않으면 공식 요구조건을 확인하고 macOS에서 필요한 설치 한 단계만 안내하세요. 설치되지 않은 도구의 성공을 가정하지 마세요. 문서 정리 등 가능한 일은 마무리하세요.

3. 변경할 파일과 이유를 5줄 안팎으로 설명한 뒤, 일상적인 파일 생성/패키지 설치/검증은 이어서 진행하세요.

4. 기술 선택:
- Next.js 안정 버전, TypeScript strict, App Router, React, npm.
- 공식 요구조건에 맞는 Node LTS를 선택하고 실제 사용 버전을 README와 .nvmrc에 기록하세요.
- npm lockfile을 남기고 다른 패키지 매니저 lockfile을 추가하지 마세요.
- 필요한 최소 스타일링만 사용하세요. Express, Redis, Zustand, ORM, 결제 SDK, AI SDK, 대형 UI 라이브러리는 추가하지 마세요.
- 생성기가 만든 최신 Next 전용 지침에 유용한 내용이 있으면 프로젝트 AGENTS.md를 보존한 채 필요한 참고만 병합하세요.

5. 이번 화면/API:
- / : 틈예약 소개. ‘1인 샵의 예약을 한곳에서 관리합니다’라는 목적과 개발 초기 상태를 명확히 표시합니다. 한국어로 작성하고 모바일 대응을 적용합니다. 색상·서체·레이아웃은 docs/DESIGN.md를 따릅니다.
- /setup : 로컬 개발 연결 상태 안내. 이 단계에서는 인증/예약/DB가 아직 구현되지 않았음을 보여줍니다. 환경변수 존재만으로 ‘연결 성공’을 표시하지 마세요. 비밀값을 응답이나 화면에 출력하지 마세요.
- GET /api/health : 런타임 상태만 확인할 수 있는 최소 JSON을 반환합니다. DB 건강 상태를 확인한 것처럼 표시하지 마세요.
- 실제 저장/로그인/입금/예약 확정이 없는 데모 성공 흐름은 만들지 마세요.

6. 개발 기본 파일:
- .env.example은 필요한 공개 Supabase URL/공개 키의 빈 자리와 설명만 둡니다. 아직 사용하지 않는 서버 비밀키를 요구하지 마세요.
- .env.local과 비밀 파일이 Git에 들어가지 않도록 .gitignore를 설정합니다. .env.example은 추적 가능하게 유지합니다.
- dev/build/start/typecheck/lint 스크립트를 설정합니다. 설치한 Next 버전이 제공하지 않는 오래된 명령은 사용하지 마세요.
- README에 실제 설치·실행 명령과 아직 미연결인 기능을 기록합니다.
- Git이 준비되어 있고 저장소가 없다면 이 폴더에서만 초기화할 수 있습니다. 원격 저장소 생성·push·배포는 이번 작업에 포함하지 않습니다.

7. 검증:
- typecheck, lint, production build를 실행하고 실패하면 이번 범위 안에서 원인을 고치세요.
- 개발 서버를 실제로 실행하여 /, /setup, /api/health의 응답을 확인하세요. 환경변수 없는 상태도 정상 안내해야 합니다.
- 브라우저 도구가 가능하면 모바일 폭·새로고침·기본 이동을 확인하세요. 불가능하면 ‘브라우저 미검증’으로 기록하고 제가 확인할 URL과 행동을 주세요.
- 단순 뼈대만을 위한 거대한 자동 테스트 도구는 추가하지 마세요.

8. 완료 보고는 docs/WORKLOG.md에 남기고 아래 형식으로 답하세요.
- 최종 프로젝트 폴더와 선택한 버전
- 변경한 파일과 이유
- 실행한 명령 및 실제 성공/실패 결과
- 로컬 확인 URL과 확인할 행동
- 실제 동작하는 부분 / 아직 없는 부분
- 해결되지 않은 오류와 다음 단계에 필요한 입력

이 단계에서 Supabase 계정을 만들거나 API 키를 채팅에 요청하지 마세요. 예약/예약금/인증을 한꺼번에 구현하거나 외부에 배포하지 마세요. 첫 기반이 검증되면 그 결과를 보고하고 마무리하세요.
```
