# 한 기능 구현 후 검토 요청문

기능 구현자가 남긴 Git diff와 WORKLOG가 있는 프로젝트에서 사용합니다. 처음에는 읽기만 하고, 구체적인 결함이 확인되면 그 결함의 수정 작업을 다음으로 맡깁니다.

```text
현재 작업의 구현 결과를 검토해 주세요. AGENTS.md, 해당 PRD/동작 규칙, 최근 WORKLOG와 Git diff를 먼저 읽으세요.

이번 검토는 코드를 변경하지 말고, 다음을 근거 파일·동작과 함께 확인해 주세요.
1. 요청한 범위와 실제 변경이 일치하는가?
2. 새 기능이 기존 예약·입력 보존·권한·재시도 동작을 깨뜨리는가?
3. DB 트랜잭션, 겹침 방지, 멱등성, RLS/서버 권한이 실제로 적용됐는가?
4. 예약금 신고와 입금 확인, 일정 취소와 환불 처리를 혼동하지 않는가?
5. 테스트가 실제로 실행됐는가? 환경·결과·미실행 부분이 구분되는가?
6. 비밀값이나 고객 정보가 코드·로그·응답에 드러나는가?

현재 단계와 관계없는 항목은 적용 대상 아님으로 분리하세요. 의례적인 개선 제안을 늘어놓지 말고, 실제 오류와 출시를 막는 구체적인 위험을 우선하세요.

결과:
- 바로 고쳐야 할 문제: 위치, 재현 조건, 영향, 최소 수정안
- 현재 범위에서 통과한 근거
- 확인할 수 없었던 항목과 필요한 검증
- 다음 작업 진행 가능 여부와 이유

검토하지 않은 파일이나 실행하지 않은 테스트를 확인했다고 쓰지 마세요. 고객 데이터·자격증명은 보고에 포함하지 마세요.
```
