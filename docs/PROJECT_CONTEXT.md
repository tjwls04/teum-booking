# 프로젝트 컨텍스트

기준일: 2026-11-27 (Asia/Seoul)

## 사용자가 직접 확인한 사실

- 만들 제품은 샵인샵 및 반영구·1인 프리랜서 사업자용 예약관리 프로그램이다.
- 사용자 설명에 따르면 대상 사업자는 카카오톡으로 예약을 받고 수기로 옮겨 적는 경우가 많다. 아직 시장 전체에 대한 조사 결과는 아니다.
- 고객은 복잡한 절차 없이 예약하고, 겹치는 시간은 자동으로 막혀야 한다.
- 사업자는 반복 답장·수기 입력을 줄이고 휴대폰 또는 카카오 알림을 받고 싶다.
- 사업자마다 일정은 독립적이다. 공유 베드나 공동 자원 예약은 요구하지 않았다.
- 예약금 사용 여부와 조건은 각 사업자가 설정하기를 원한다.
- 실제 검증에 협조 가능한 사업자는 현재 1곳이며 더 찾을 계획이다.
- 첫 상용 출시는 유료로 생각하고 있다. SaaS 월 이용료는 아직 최종 결정 전이다.
- 운영자는 아직 사업자등록 전이다.
- 개발·초기 테스트는 무료 범위로 시작하고, 상용 운영 약 US$32/월과 필요한 추가 비용은 가능하다고 답했다. 이를 고정 상한이나 유료 상품 자동 구매 승인으로 해석하지 않는다.
- 개발 환경은 macOS + Cursor. 코드와 별도 DB를 본인이 소유·관리하고 싶다.
- 학습한 도구는 JavaScript, TypeScript, React, Next.js, Node.js, Express, Zustand, Redis, Supabase, Google Cloud, Sentry, Render, Postman, GitHub이다.
- ChatGPT Plus 및 Claude Code 구독을 사용한다고 밝혔다. Claude의 정확한 상품/사용 한도는 확인하지 않았다.
- 디자인 방향과 색상·서체는 [DESIGN.md](DESIGN.md)에 확정했다. 필요한 도구의 선택은 위임했다.

## 우리가 제안하는 제품 정의

> 고객이 링크에서 빈 시간을 골라 예약하면, 사업자의 일정에 자동 반영되고 같은 시간이 중복 예약되지 않는 1인 샵 예약관리 웹서비스.

웹서비스를 휴대폰 중심으로 설계한다. 고객 앱 설치는 요구하지 않는다. 사업자용 계정과 고객용 공개 예약 페이지를 구분한다.

## 대표 프로토 페르소나

혼자 시술하며 샵 공간을 빌려 쓰는 사업자. 시술 중 문의에 답하지 못하고, 가능한 시간을 확인해 답한 뒤 예약을 일정에 옮겨 적는다. 이 구체적인 업무 장면은 인터뷰로 확인할 가정이다.

핵심 가설: 고객이 예약 링크를 직접 사용하면 사업자가 일정 확인·안내·전사에 쓰는 시간이 줄어든다. 예약금 수동 확인이 남는 경우 그 시간을 따로 측정한다.

## 개발 방식

- 사용자는 로컬 코드, 개인 GitHub 저장소, 개인 Supabase 프로젝트, 개인 Render 서비스를 소유한다.
- ChatGPT는 기획·설계·개발 요청문·완료 판정 기준을 제공한다.
- Cursor의 Codex를 기본 구현 도구로 쓴다. Claude Code로 바꿀 때도 같은 문서와 현재 Git 상태를 전달한다.
- 이번 제품 자체에 AI 모델을 넣을 필요는 없다. 로컬 LLM이나 상용 LLM API 키는 준비물이 아니다.
- 기존 Sites 프로토타입은 UI·규칙·테스트 시나리오의 참고 자료다. 새 프로젝트는 native Next.js/Supabase 환경에서 다시 검증한다.

## 단계별 필요한 입력

| 단계 | 필요한 것 |
| --- | --- |
| 첫 로컬 실행 | 이 문서 폴더, Cursor, Node/npm, Git |
| 코드 보관 | 본인 GitHub의 비공개 저장소 |
| 인증·DB 연결 | 본인 Supabase 개발 프로젝트와 로컬 환경변수 |
| 실사용 가입 | 인증 이메일용 SMTP 설정 및 발신 도메인 확인 |
| 상용 배포 | 본인 Render 서비스·Supabase 운영 프로젝트·도메인·운영 설정 |
| 유료 판매 | SaaS 이용료 수납 방식, 실제 운영자 정보·이용/해지 정책 |
| 카카오 발송 | 발신 주체, 채널·딜러·템플릿 승인과 발송 설정 |

계정 비밀번호나 비밀키는 이 대화에 제출하지 않는다. 해당 서비스와 로컬 설정에 직접 입력한다.
