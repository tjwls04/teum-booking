# 틈예약 MVP PRD v0.2

기준일: 2026-11-27 · 상태: 제품 기능 설계안 · R6 사업자 예약 관리 실검증 완료 · R7 예약금 관리 구현, R7 원격 적용 전

## 1. 목표와 판단 기준

샵인샵·1인 사업자의 반복 예약 답장과 수기 전사를 줄인다. 고객은 가입 없이 시술·시간을 고르고 예약하며, 사업자는 하나의 일정에서 예약과 막아 둔 시간을 확인한다.

첫 검증 대상은 협조 가능한 사업자 1곳이다. 먼저 그 샵의 최근 예약 3건에서 문의→시간 협의→예약금→확정→취소 과정을 확인한다. 전체 시장의 빈도나 지불 의사를 인터뷰 한 곳으로 일반화하지 않는다.

제품 효과와 소프트웨어 안전성을 구분한다. 답장 감소는 실제 사용에서 확인하고, 중복예약·권한·저장 문제는 별도 자동 테스트로 확인한다.

## 2. 범위

### 포함

- 사업자 이메일 기반 가입·로그인·로그아웃·비밀번호 재설정.
- 사업자당 1샵, 1인 시술 일정. 샵끼리 고객·예약·설정을 공유하지 않는다.
- 시술명, 설명, 소요시간, 준비시간, 가격, 공개 여부 설정.
- 요일별 영업시간, 휴식, 임시 차단, 최소 예약 여유, 예약 가능 기간, 취소 가능 기한.
- 고객 무가입 예약, 서버 영속 저장, 중복 방지, 결과 불확실 시 복구.
- 사업자 일간·주간·월간 일정, 예약 목록·상세, 수동 등록, 시간 변경·취소·완료·노쇼 기록.
- 고객의 확인 링크 조회 및 허용된 범위의 취소.
- 예약금 없음/고정 금액 선택과 사업자 직접 수납을 위한 계좌 안내·확인 상태. 세부 규칙은 BOOKING_RULES 참고.
- 앱 안 알림 및 사업자 Web Push. 카카오 알림톡은 실제 승인 후 연결한다.
- 상용 출시 전에 SaaS 월 이용료 수납·권한 처리. 고객 예약금과 구분한다.

R4의 최초 샵 등록은 기존 R2 스키마의 상호와 공개 주소를 사용한다. 영업시간과 시술은 샵 등록 후 각각 설정한다.

### 후속 검토

직원 여러 명, 복수 지점, 공유 베드, 고객 회원가입, 포인트·회원권, CRM 마케팅, 사진·건강 정보 업로드, AI 상담, 카카오 대화 분석, 플랫폼의 예약금 수납·샵별 자동 정산, 일반 은행계좌 자동 입금 확인, 자동 환불.

## 3. 기본값 — 첫 샵 테스트에서 조정할 제안

| 항목 | 제안 |
| --- | --- |
| 시간대/통화 | Asia/Seoul / 정수 원(KRW) |
| 예약 간격 | 15분; 시술·준비시간도 15분 단위 |
| 최소 예약 여유 | 2시간 |
| 예약 가능 기간 | 기본 60일, 서울 기준 오늘을 포함해 최대 90일 |
| 고객 취소 기한 | 기본 예약 시작 전(0시간); 사업자가 설정 |
| 예약금 기본 | 사용하지 않음 |
| 예약금 사용 시 | 시술별 고정 금액, 0보다 크고 시술 가격 이하 |
| 입금 신고 기한 | 기본 60분, 샵이 30/60/120분 중 선택; 예약 시작을 넘지 않음 |
| 샵 계좌 | 은행/계좌번호/예금주; 예약금 사용 시 필수 |
| 초기 가격안 | SaaS 월 9,900원, 부가세 포함, 월 단위; 아직 지불 의사 검증 전 |

취소 가능 기한은 취소 기능의 조건이다. 예약금 환불 액수·가능 여부를 이 값만으로 결정하지 않는다. 사업자별 정책을 고객에게 보여주고 예약 당시 버전을 남기며, 실제 환불은 사업자가 별도로 처리한다.

## 5. 예외 상황의 필수 동작

- 빈 이름·전화번호 오류·필수 동의 누락: 저장하지 않고 필드별 안내.
- 다른 고객이 먼저 예약: 입력을 유지하고 시간만 다시 선택.
- 본 뒤 가격/시간/예약금/계좌/취소 정책 변경: 변경 내용을 다시 보여주고 확인을 요청.
- 네트워크 단절: 결과 미확정 상태를 보존하고 같은 요청으로 확인. 중복 새 요청 생성 금지.
- 목록 조회 실패: 빈 목록과 오류를 구분하고 재시도 제공.
- 예약금 신고 기한 경과: 자동으로 다시 확정하지 않음. 실제 입금했다면 사업자 문의·확인 처리.
- 알림 실패: 예약은 유지하고 전송 실패를 별도 표시.
- 인증 만료: 개인정보를 숨기고 로그인 안내. 권한 없는 샵 접근 거절.

## 6. 출시의 구분

1. 로컬 개발: 가짜 데이터와 미연결 상태를 명확히 구분.
2. 비공개 샵 테스트: 1곳에서 실제 업무 흐름과 휴대폰 사용성 확인. 아직 일반 유료 판매와 구분.
3. 첫 상용 출시: 실제 저장·권한·예약금 상태·알림을 확인하고, SaaS 수납·해지·운영자 정보·개인정보 처리 안내를 준비한 뒤 유료 제공.

‘첫 상용 출시 유료’라는 요구는 유지한다. 결제 버튼만 보이거나 테스트 결제만 성공한 상태를 유료 서비스 운영 완료로 보고하지 않는다.

## 7. 첫 샵에서 기록할 지표

- 최근 예약 3건의 수동 메시지 왕복 횟수와 옮겨 적는 과정.
- 링크 예약 시도 건수와 완료 건수. 단순 페이지 열람을 예약 시도로 세지 않는다.
- 사업자가 직접 개입한 단계와 횟수. 예약금 수동 확인은 별도로 센다.
- 겹침/누락/잘못된 상태/알림 미수신 건수 및 원인.
- 제안 월 요금에서 실제 유료 이용 의사와 거절 이유. 한 샵의 의견을 시장 검증 완료로 쓰지 않는다.

안전성 오류가 발견되면 원인 수정·재검증 전 실사용 범위를 늘리지 않는다. 성공 전환율 숫자는 데이터를 보기 전 임의로 약속하지 않는다.
