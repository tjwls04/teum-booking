# 결정 기록

기준일 2026-11-27. 사용자 확인 사실과 설계 제안을 구분한다.

## 사용자 확인

- macOS + Cursor에서 코드 관리.
- 시각 콘셉트는 Premium Editorial × Modern SaaS로 확정. 색상·서체·화면별 기준은 [DESIGN.md](DESIGN.md).
- 사용자 소유 GitHub/별도 DB를 바라는 방향.
- 사업자별 독립 일정.
- 예약금은 각 사업자가 설정.
- 첫 테스트 사업자 1곳, 추가 모집 예정.
- 상용 운영 약 US$32/월 및 필요 추가비용 가능.
- 아직 사업자등록 전, 첫 상용 출시는 유료 지향.

## 이번 작업에서 채택한 설계 제안

| 결정 | 이유 | 재검토 시점 |
| --- | --- | --- |
| native Next + Supabase + Render | 배운 기술과 소유/이식성 요구를 함께 충족 | 구체적 성능·비용 문제 발생 시 |
| 1샵·1시술자, 고객 무가입 | 사용자가 지정한 독립 1인 업무 | 공동자원/직원 요구가 실제 발생 시 |
| 시술별 없음/고정 예약금 | 시술별 차이를 한 값으로 표현 | 첫 샵 인터뷰 후 |
| 샵 직접 이체·수동 확인 | PG/플랫폼 정산 없이 초기 검증 | 자동화 수요와 계약 가능성 확인 후 |
| 신고된 입금은 자동 만료하지 않음 | 실제 입금한 고객의 시간을 잘못 재판매하지 않도록 | 첫 샵 확인 부담·허위신고 관찰 후 |
| 기본 신고기한 60분/취소 시작 전 | 구체적 구현 출발값; 시장 표준이라는 주장 아님 | 첫 샵 운영 조건 확인 후 |
| 월 9,900원 VAT 포함 가격안 | 한 플랜으로 지불 의사 검증 | 실제 유료 제안·지원비용 확인 후 |
| 첫 프롬프트는 기반만 구현 | 오류가 생기는 위치를 좁힘 | R1 결과 후 R2 요청문 작성 |

사업자 설정 가능이라는 요구는 확인됐지만, 고정 금액·수동 이체·기한 값은 총괄 담당자의 초기 설계 제안이다. 사용자가 변경하면 관련 PRD/동작/테스트를 함께 바꾼다. 현재 첫 기반 작업을 막는 결정은 아니다.

## 이후 실제 선택할 항목

브랜드/도메인 확정, SMTP 제공사, SaaS 유료 수납 방식/PG 계약, 카카오 발신 주체·제공사·템플릿, 실제 운영자 정보·정책, 데이터 보관 기간.

이 항목이 아직 없다고 로컬 UI·DB·예약 구현을 중단하지 않는다. 해당 기능의 실사용 활성화 전에 구체적인 설정으로 마무리한다.

## 기존 프로토타입과 다른 점

- 인증: Sites ChatGPT 로그인 → Supabase Auth.
- DB: D1/SQLite → PostgreSQL.
- 런타임: Vinext/Worker → native Next/Node.
- 예약금: 보류 → 사업자 설정 및 수동 확인 포함.
- 기본 고객 취소 기한: 이전과 같이 시작 전으로 유지하며 사업자가 조정한다. 환불 규정과 구분한다.
- 기본 가격: 미정 → 월 9,900원 VAT 포함 제안. 판매/결제 확정이 아님.
